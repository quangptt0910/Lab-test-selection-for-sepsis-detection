# ADR-0008: Experiment runner

Status: accepted (M3-1). Code in `sepsis.eval.{experiment_config,tables,runner,run_experiment}` and `sepsis.risk.base`.

## Context
Every risk-model experiment (B0–B3, ablations) must be run, scored and logged the same way under the three setups of ADR-0004. The pieces existed (split helpers, the view, the feature builder, the U1 − U0 target, the scorer and threshold tuning, ADR-0007), but nothing joined them, and several choices were open: which view a model is fitted and scored on, how a model plugs in, where results go, and what a partial run means. Building the view, features and targets for all dev patients took about 2.3 min per experiment, most of it the same work each time.

## Decision
1. **One command.** `uv run python -m sepsis.eval.run_experiment configs/<name>.yaml [--allow-dirty] [--no-cache]`. The `run-experiment` skill runs its pre-flight checks, calls this command, then compares the new LOG row with earlier ones.
2. **Strict config schema.** Required: `id, hypothesis, seed, split.setups, features.hand_crafted, features.lab_masking_p, features.signatures (null until M4), target, model.type, model.params, note`. Unknown keys are refused. The threshold grid is not an experiment setting: it comes from `configs/eval.yaml`.
3. **Which view for what.** Models are fitted on features from the **training view** (as recorded, panel-draw masking with the experiment's `lab_masking_p` and `seed`). Out-of-fold predictions (for threshold tuning) and scored predictions use the **evaluation view** (as recorded, no masking). Replay (M5) replaces the evaluation view's reveals with the policy's.
4. **Build once, select folds.** Both feature tables and the targets are built once for all dev patients, aligned row by row, and folds select rows. This is safe because features are pure per patient and masking is seeded per patient (ADR-0006); a test checks that a patient's rows don't depend on the other patients in the table. Targets are attached after the features are built, and the runner refuses label or key columns among the features.
5. **Cache.** The tables are stored as parquet under `data/cache/features/` (gitignored), keyed by the cleaning, panels, features and labels configs, the chosen blocks, `lab_masking_p`, `seed` (training table only), the split fingerprint, the patient set and the source code of `sepsis.data`, `sepsis.features`, `sepsis.labels`, `eval/tables.py` and `config.py`. A cache is written to `<key>.tmp` and renamed when complete. `--no-cache` rebuilds.
6. **Model interface.** `RiskModel` with `fit(X, y, sample_weight) -> self` and `predict(X) -> raw score` (`sepsis.risk.base`). `make_model(type, params, seed)` builds a fresh model for every fit, so no state moves between folds. Every fitted statistic lives inside `fit`. `predict` never returns class labels: the alarm is `score > threshold` with the threshold tuned on the training side. `target` is `utility_diff` or `sepsis_label`; both are trained with the target weight (0 for septic hours with dt > 3).
7. **Setups.** A → B and B → A: 5-fold CV over the training hospital's stored dev folds gives out-of-fold scores, the threshold is tuned on them, and a model refit on the whole training dev part scores the other hospital's dev part. Mix: for each outer fold k, an inner CV over the other 4 folds tunes fold k's threshold, a refit on those 4 folds scores fold k, and the 5 held-out folds are pooled and scored per hospital. Every model predicts only patients it was not fitted on (tested).
8. **Partial runs.** `split.setups` may be any non-empty subset. Setups not run are `—` in the LOG, the AUROC column says `(k of 4)`, and the note says "partial run: not comparable". A partial run is never used to keep a change.
9. **Run folder.** `experiments/runs/<id>/` (gitignored): the config, the resolved configs, the feature columns, `meta.json` (git SHA, dirty flag, command, seed, cache keys and hit, scorer hash, package versions, timings), and per setup the thresholds, threshold curves, fold statistics and predictions. It is written as `<id>.partial` and renamed after the LOG row is appended, so a crash leaves no LOG row and the id can be rerun. Scorer `.psv` folders are temporary. **No models are saved**: with a fixed seed any model can be refit, so replay (M5) refits.
10. **LOG row and refusals.** One row per run, appended only after every setup finished: utilities to 3 decimals, mean AUROC, `—` for labs per patient-day until replay, `eval` = `dev`. A duplicate id (exact match on the id cell) or a finished run folder is refused before any work. A dirty tree (tracked files changed, `experiments/LOG.md` excepted) is refused unless `--allow-dirty`, which adds `-dirty` to the SHA. Red flags that need no earlier run (any AUROC > 0.95; A → B and B → A differ by more than 0.15; a cross-hospital result beats mix for the same hospital) are printed and written into the note. The "utility jumps by more than 0.05" flag compares with earlier rows and stays in the skill.

## Consequences
- Every experiment is compared on the same folds, thresholds rule and scorer, and A-test and B-test are never loaded (tests patch the all-patient readers to fail).
- A repeated experiment with the same features and seed skips the table build. Any change to the configs or to the code that builds the tables gives a new cache key.
- One full experiment is 37 model fits (A → B 6, B → A 6, mix 25) plus 7 threshold tunings. On all dev patients a tuning takes about 26 s and one official-scorer call about 3 min (it writes one file per patient), so the scorer dominates a run with a fast model.
- Untracked experiment configs do not make the tree dirty; the config is copied into the run folder.
